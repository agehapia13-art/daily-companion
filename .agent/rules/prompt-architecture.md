# 生活伴走システム プロンプト設計・改修ガバナンスルール

本プロジェクト（`daily-companion`）におけるシステムプロンプトの改修・改善を行う際、エージェントは必ず以下の原則とアーキテクチャを厳格に順守しなければならない。

---

## 1. プロンプト設計の4大原則

### 原則1: Principles over Examples（具体例排除・原則ベース）
* **背景**: `gemini-3.8-flash`（思考バジェット0）はプロンプト内の具体例を抽象カテゴリではなく「固定トークン（出力ひな型）」として記憶（アンカー効果）してしまう。
* **ルール**:
  * プロンプト本文内に具体的な行動例（例:「白湯を飲む」「顔を洗う」「穏やかな音楽」「ストレッチ」等）を一切記載してはならない。
  * すべて**「認知的・身体的負荷（極小〜高）」「覚醒度」「所要時間」「姿勢・場所（ベッド/手元/移動）」などの客観的属性と生活力学の原則**で定義すること。

### 原則2: Generalizability（シーン・時間帯の普遍性）
* **背景**: 「朝だから白湯」「夜だから入浴」といった個別シーンへの対症療法パッチを繰り返すと、プロンプトが肥大化し応用性が失われる。
* **ルール**:
  * 朝・昼・夜・休日・作業合間などの特定時間帯に依存させず、**普遍的な状態遷移（低覚醒状態からの移行、固定予定までの可処分時間ブロックの発生、作業の一区切り等）**として定義すること。

### 原則3: Orthogonal 4-Layer Architecture（直交4層構造の維持）
プロンプトは以下の直交した4セクションで構成し、重複や境界の曖昧化を防ぐこと：
1. **第1層: 基本姿勢・境界ルール**: 人格、主語・視点の厳密な分離、直前の単発物理行動（送り出し即座終了）と可処分時間目標の明確な境界。
2. **第2層: 生活リズム・生体状態基準**: 睡眠・起床の健康軸、覚醒・休息の状態遷移基準。
3. **第3層: 意図分類（Intent Classifier）**: 発言の意図（直前物理行動 / 可処分時間の目標表明 / 完了報告 / 質問 / 相談）を正確に分類。
   * **バトン渡しの1ステップ限定**: 完了報告後に余白がある場合でも、言及するのは【直近の次の一手（1アクション）】のみに限定する。「〜しつつ、準備ができたら〜しよう」といった条件付き複数フェーズ結合（先回り）は厳禁。
4. **第4層: 提案・段取りエンジン**: 4プール横断・4属性フィルタ・異種ポートフォリオ分散に加え、まとまった空き時間に対する無理のない見通し・段取り提案。
   * **生活前提の尊重**: 生活に必要な準備や休息の時間を考慮した上で、現実的な時間配分を見立てること。




### 原則4: Verification via Scenario Testing（テスト検証の義務）
* プロンプトを変更する際は、必ず複数のテストシーン（`scripts/test-prompt.js` または `src/Setup.js`）で検証すること。
* 「提案しなさすぎる（過剰萎縮）」「先回り・小言（過保護）」「特定行動への偏り（アンカー）」の副作用が発生していないかを客観的に確認してからスプレッドシートへ反映すること。
