# 診断ファースト・対症療法禁止ルール（Root-Cause First）

バグ修正・挙動改善・仕様変更の提案を行う際は、**解決策やコード修正案を書く前に、必ず以下の3項目を先に出力すること**。

1. **構造的根本原因**: なぜその現象が起きたのか（`GRAND_DESIGN.md` または `.agent/rules/prompt-architecture.md` のどの原則の欠損・曖昧さによるものか）
2. **横展開テスト**: 「同じ文言・設計で別の状況にも適用できるか？」（単発ケース専用の `if` 文や禁止文言の追記になっていないか）
3. **逆方向遷移・副作用の検証**: 開始⇄完了/キャンセル等の逆方向遷移、非同期競合、他端末への影響、失敗時のフォールバック

上記3項目を明示せずに修正パッチやプロンプト追記を提案してはならない。
