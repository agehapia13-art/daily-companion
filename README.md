# 生活伴走システム（LINE Bot × GAS × Gemini 3.1 Flash-Lite & 3.8 Flash）

サウンドディレクター専属の生活伴走アシスタントとして、LINE・Google Apps Script (GAS)・**Gemini 3.1 Flash-Lite（司令塔・ルーター）＋ Gemini 3.8 Flash（本思考・動的アセンブル）**・Googleスプレッドシート・Googleカレンダー・Notion API・Open-Meteoを完全統合したパーソナル自動化システムです。

> 🧭 **最高憲章**: 本システムの存在意義・思想定義・行動原理は [GRAND_DESIGN.md](GRAND_DESIGN.md) に完全定義されています。すべての機能・プロンプト・改修は本グランドデザインを北極星として設計されます。

---

## 🌟 システムの特徴と主要アーキテクチャ

### 1. 2モデル・2段階ハイブリッドアーキテクチャ（超低遅延・トークン極小化）
- **第1段階: 司令塔・ルーター（`gemini-3.1-flash-lite`）**:
  - ユーザー発言の意図分類（DB依頼、単発行動開始、過ごし方相談、体調不良、雑談等）、直前行動の状態、着目すべきタスク、該当する生活習慣トピックなどを、Structured Outputs（厳密なJSONスキーマ）で超低遅延・高精度に高速判定。
- **GAS ルール層: 客観数値の機械的算出 ＆ 生活フェーズ判定**:
  - 前回のやり取りからの経過時間、次の生活境界（仕事・食事・就寝等）、未完了タスク・カレンダー予定の客観データをGAS側で機械的に集計し、状況に応じたフェーズ（Phase A: 進行中保護 / Phase B: 即時送り出し / Phase C: 余白・触媒提案 / Phase D: 通常対話）を確定。
- **第2段階: 本思考・動的アセンブル実行（`gemini-3.8-flash`）**:
  - 判定結果に基づき、必要なプロンプト断片（`prompt_core`, `prompt_phase_*`, `prompt_db`, `prompt_relief`）と必要最小限のコンテキストのみを動的に結合して注入。
  - 思考トークン無効化（`thinkingBudget: 0`）により、LINE Reply APIのタイムアウト（数秒）を余裕でクリアする即時応答性を実現。
  - **消費トークンの激減**: 旧システムの単一巨大プロンプト（約4,500〜6,500トークン）から、**1,000〜1,500トークン（約70%削減）** へ劇的にフットプリントを圧縮し、低コスト運用を確立。

### 2. 完全コストゼロ運用（LINE Reply API限定）
- Push APIは一切使用せず、全対話・通知を無料の **Reply API** のみで完結。
- 深夜バッチも通知なしの完全サイレント処理。

### 3. 睡眠ファースト ＆ 起床連動（ファースト・ハロー方式）
- 起床時間（朝4時〜正午まで）の初回の発言（「作業する」「おはよ」等）の返信末尾に、**天気（最高/最低気温・降水確率）・当日活動時間帯（06:00〜24:00）の気圧急降下アラート・本日の予定・重要タスク（当日＆期限超過の未完了タスク）**をまとめたデイリーブリーフィングを自動合流（正午以降や2回目以降の発言では誤発動しないガード付き）。
- **出社予定連動の天気取得**: 本日の予定（メイン＋家族共用「♪」予定）に「出社」が含まれる日のみ「自宅(磯子)＋職場(渋谷)」の両方の天気を取得・表示し、在宅日は「自宅(磯子)」のみを表示してノイズを排除。
- **プログラム制御による二重配信防止**: AIの出力に任せず、`PropertiesService` とスプレッドシート `memory` の両面ガード（`isBriefingDeliveredToday` / `markBriefingDeliveredToday`）で1日1回だけ確実に配信。

### 4. 安心の単一ユーザーセキュリティ（あなた専用）
- あなたのLINE User ID（`OWNER_USER_ID`）のみを受け付けるホワイトリスト認証。
- 他者からのメッセージや偽造リクエストを即座に遮断し、予定・体調・タスクのプライバシーを保護。

### 5. 記憶の3層管理 ＆ 用語辞書（前提知識の厳格遵守）
- **短期記憶**: 当日の会話ログ（極小高密度フォーマット `HH:mm User: ... / AI: ...` で全ターン保持）。
- **中期記憶**: `rolling_memory`（最近の関心・ログ：直近7〜10日分の活動・関心バッファ）。
- **長期記憶**: `profile`（住居・家族・勤務形態などの恒久的事実。深夜バッチで厳格に代謝）。
- **用語辞書**: 『ぽこあポケモン』『残響フラクタル』『ぱずぎり』などの独自用語・作品定義をAIが世間一般の作品と混同しないよう、コンテキストに常時注入。

### 6. Web検索（Google Search Grounding）とタスク誤爆防止
- 「〇〇のイベントいつまで？」「〇〇のチケット発売日いつ？」等の質問時は、Web検索で最新・正確な期日や事実をリアルタイム調査。
- **月間5,000回まで検索完全無料**: Gemini APIにおける Google Search グラウンディングは月間 5,000 リクエストまで無料枠内で稼働。
- 調べた時点では勝手にタスク追加せず、「タスクに追加しておきましょうか？」と確認を添え、次のターンで「追加して」と言われた際に初めて期限付きタスクとして登録。

### 7. Googleカレンダー双方向連携 ＆ 家族共用カレンダー安全参照
- **メインカレンダー**: 読み取りおよび追加・削除に対応。毎週の曜日繰り返し予定（`recurrence_days: ["MON", "THU", "FRI"]`）にも対応し、重複単発予定を自動クリーンアップ。
- **家族共用カレンダー（`FAMILY_CALENDAR_ID`）**: 【完全読み取り専用】。ユーザー担当の「♪」付き予定のみを抽出してデイリーブリーフィングやスケジュール把握に活用。

### 8. 自律性と対等性を尊重した行動提案 ＆ スマートな生活伴走
- **原則ベースの行動提案エンジン（5領域横断・ポートフォリオ分散・同日重複排除）**:
  特定の定番行動への偏りを防ぐため、[①実務・家事 / ②創造・専門スキル / ③文化・教養・娯楽 / ④身体ケア・休息・日常手入れ / ⑤社会的・対外的行動] の全5領域を横断。現在のユーザー状態（所要時間・負荷・覚醒度・姿勢）と照合して提案。
- **生活習慣・運動の多様性（`lifestyle_habits`）**:
  散歩だけでなく、室内ストレッチ動画、自重筋トレ動画、フィットネスゲーム（フィットボクシング、リングフィット等）など、屋内外の多様な身体ケア選択肢を生活前提データから動的に参照・提案。
- **周期メンテナンスとご無沙汰スキルの可視化（`cycle_stamps`）**:
  美容院、弦交換、シーツ洗濯、楽器演奏、スケッチ等の最終実施日を記録し、経過日数（例: `3日前`）を動的にアノテーションして提案エンジンへ連携。
- **起きてから寝るまでの明瞭なタイムスケジュール設計（Phase C）**:
  休日の過ごし方相談などでは、大雑把な時間帯区分（午前・夕方等）で濁さず、起床から就寝まで `HH:mm〜HH:mm` の具体的な時間ブロックで1日の見通し・段取りを網羅的に提示。固定予定や生活習慣のアンカー時刻を尊重し、空き時間には未完了タスクやストック消化を自然に配置。
- **行動宣言に対する時間軸の限定（1文完結・先回りの完全排除）**:
  「風呂入ってくる」「ご飯炊いてくる」などの行動宣言時は、その宣言された行動への了解と送り出しの1文のみで即座に完結。条件付きの先回り（「沸いたら〜しよう」等）を排除。
- **大人の自律性尊重と予防的小言の排除**:
  日常の生活行動に対して、怪我・冷え・体調に関する予防的気遣いフレーズ（「〜に気をつけて」等）を口出ししない。
- **主語・視点の厳密な分離**:
  AIは「聞き手・伴走者」であり行動の当事者ではない。ユーザーの食事や帰宅に対する「ごちそうさまでした」「ただいま」や、セルフケアへのお礼（「ありがとうございます」）などの主客転倒を厳禁化。
- **タスク優先度・リマインド目安の動的更新（口頭承諾の完全排除）**:
  ユーザーが「〜を優先度高めで提案してほしい」「早めに提案して」「〇〇を優先して」などと発言した場合、単なる口頭の相槌で終わらせず、前段Flash-Liteが確実にDB更新操作（`task_update`）としてルーティング。後段Flashがスプレッドシート `tasks` のメモ欄（背景・理由）およびリマインド目安（8列目: 例 `休日PC・最優先`）を即座に更新・永続化。

### 9. スプレッドシート連動によるモジュール型プロンプト運用（完全ノーデプロイ）
- **モジュール型プロンプト体系**:
  スプレッドシートの `memory` タブ（`prompt_core`, `prompt_phase_a~d`, `prompt_db`, `prompt_relief`, `prompt_lite`）に各モジュールを分割保持。
- **完全ノーデプロイでのプロンプト即時反映**:
  GASエディタでの再デプロイ（新バージョン発行）は一切不要。スプレッドシートの該当セルを書き換えるだけで、次のLINEメッセージから即時反映（追加遅延0ms）。
- **Antigravity CLI連携（`scripts/sheet-cli.js`）**:
  サービスアカウント経由で、チャットやCLIから直接モジュールプロンプトを個別に読み書き可能。

### 10. 深夜03:00統合バッチ (Notion日報・月報連携)
- 当日の会話ログ、完了タスク、および当日に消化完了したインプット作品（映画・音楽・本・ゲーム等）を集約し、GeminiでMarkdown日報を生成してNotion日報DBへ投稿。
- **Notionリッチテキスト完全対応**: 太字（`**...**`）のインラインアノテーション、区切り線（`divider` ブロック）にネイティブ対応。
- **思い出の写真自動埋め込み**: LINEで送信された画像（Google Drive保存）の中から、料理・風景・記念スクショなど日記として価値のある特筆すべき写真を厳選し、Notion日報および月報に自動埋め込み。
- **振り返りの質向上**: AI側の返答・推測・相槌をインプットから除外し、箇条書き主体で数秒で把握できる視認性を確保。
- **Notion投稿成功を確認してから**ログをクリアするデータ保護設計。また、Gemini APIの一時的な高負荷（503/429）に対する自動リトライ機構を完備。
- 毎月1日には前月日報を日付昇順で自動集約し、月間ハイライト・思い出ジャーナルをNotion月報DBへ投稿。

### 11. 生活伴走Webダッシュボード（GitHub Pages × LIFF × LINEリッチメニュー）
- **スプレッドシートの`logs`以外（全5タブ）をスマホで直感操作できる専用SPA**:
  - 🌿 **タスク**: 未完了タスク一覧、プレフィックス別グループ表示、締切順並び替え、本文タップでの編集・破棄モーダル。
  - 🛒 **買い物**: カテゴリ別未買リスト、ワンタップ購入済チェック、クイック追加。
  - 💡 **ストック**: 映画・音楽・本・ゲーム等の未消化作品一覧、消化チェック、新規追加。
  - 🔄 **周期・記憶**: 美容院や弦交換などの「あれから○日経過」と「✨ 今日やった」ワンタップ更新、プロフィールや用語辞書の閲覧・編集。
- **GitHub Pages × LIFF 連携によるネイティブアプリ体験**:
  - **公開URL**: `https://agehapia13-art.github.io/daily-companion/`
  - ダッシュボード操作時、LIFFを通じて**LINEトーク画面にユーザー自身の緑の吹き出しで自動発言**され、AIの返信とともに当日ログへ記録。

### 12. ログ基盤 ＆ トークン追跡（30日ローリング保持）
- **スプレッドシート `logs` の9列拡張**:
  `[時刻, 発言者, メッセージ, 画像URL, AI返答, 入力トークン, 出力トークン, キャッシュトークン, 合計トークン]` をリアルタイムに永続記録。
- **直近30日ローリング保持**:
  スプレッドシート上に直近30日分の全会話ログとトークン履歴を常時保持し、手元での検証性・分析性を担保。30日を超えた古い行のみ深夜バッチで安全にパージ。

## 📊 スプレッドシート構造（全6タブ）

1. **`logs`**（会話ログ ＆ トークン追跡）:
   `[時刻, 発言者, メッセージ, 画像URL, AI返答, 入力トークン, 出力トークン, キャッシュトークン, 合計トークン]`
   （※直近30日分を常時ローリング保持。30日を超えた古いログのみ深夜バッチで安全にパージ）
2. **`tasks`**（単発タスク）:
   `[タスクID, タスク名, 期限, ステータス(未完了/完了/破棄), 登録日, 完了日, メモ]`
3. **`routines`**（繰り返し定義）:
   `[ルール名, タイプ(day_of_week/day_of_month/interval_days), 設定値, 最終生成日, メモ]`
4. **`shopping`**（買い物リスト）:
   `[品名, カテゴリ, ステータス(未買/購入済/破棄), 登録日]`
5. **`input_stock`**（映画・音楽・本のストック）:
   `[種別, タイトル, メモ, ステータス(未/完/破棄), 消化日]`
6. **`memory`**（中長期記憶 ＆ モジュール型プロンプト体系）: `[キー, 値]`
   - **記憶・前提データ**:
     - `profile`: ユーザー属性・生活前提条件
     - `dictionary`: 用語辞書（客観的前提知識）
     - `rolling_memory`: 最近の関心・ログ（直近7〜10日分の活動・関心バッファ）
     - `weekly_summary`: 直近数日間の疲労・睡眠サマリー
     - `lifestyle_habits`: 生活習慣・運動（散歩、室内ストレッチ動画、フィットネスゲーム等）・身体ケアの前提定義
     - `cycle_stamps`: 周期メンテナンス ＆ 音楽スキルアップ記録（経過日数を動的に自動注釈）
     - `weather_info`: 今日の天気・最高/最低気温・降水確率
     - `pressure_alert`: 当日活動時間帯（06:00〜24:00）の6時間以内5hPa気圧急降下アラート（TRUE/FALSE）
     - `briefing_delivered_date`: 本日ブリーフィング配信済み日付（YYYY-MM-DD）
     - `monthly_report_ready`: 月報作成完了フラグ（TRUE/FALSE）
   - **モジュール型プロンプト（設定時はコードデフォルトより最優先適用）**:
     - `prompt_lite`: 第1段階 Flash-Lite の意図判定・ルーティングプロンプト
     - `prompt_core`: 第2段階 Flash の基本姿勢・対話トーン・境界ルール（第1層）
     - `prompt_phase_a`: フェーズA（進行中行動の保護）
     - `prompt_phase_b`: フェーズB（直前の単発行動への即時了解・送り出し）
     - `prompt_phase_c`: フェーズC（まとまった可処分時間の見通し・段取り・触媒型提案）
     - `prompt_phase_d`: フェーズD（通常対話・完了労い・雑談・事実質問）
     - `prompt_db`: DB・カレンダー・タスク操作時の厳密仕様
     - `prompt_relief`: 体調不良・疲労時のケア＆引き算ルール

## 🛠️ 開発・デプロイ運用ルール

### 1. 開発とコード反映フロー（Antigravity / AI担当）

本プロジェクトは **全コードをGit（GitHub）で一元管理** し、GASへは `clasp push` で直接同期します。
コード修正時は、常に以下のワンストップフローで構文チェック・GAS反映・Git保存を行います：

```bash
# 1. src/ 配下の全ファイル構文チェック
npm run check

# 2. clasp でGASプロジェクトへコードを直接プッシュ (src/ 配下をファイル分割のまま同期)
npm run push   # (npx clasp push --force)

# 3. (ダッシュボード画面変更時のみ) docs/index.html を再ビルド
npm run build:dashboard

# 4. GitHubへ最新コードと変更履歴を保存（毎回必ずコミット＆プッシュ）
git add . && git commit -m "feat/fix: 変更内容の概要" && git push origin main
```

> [!IMPORTANT]
> **権限承認の都合上、AI側は `clasp push`（コード反映）および `git push`（リポジトリ保存）までを実施し、GASのデプロイコマンドは実行しません。**

### 2. GASエディタ側でのデプロイ更新（ユーザー手動担当）

Googleアカウントの権限設定・スコープ承認が必要となるため、**コードプッシュ後のWebアプリのデプロイ（新バージョン発行）はユーザー自身がGASエディタ上で行います**：

1. GASエディタ右上の **「デプロイ」＞「デプロイを管理」** を開く。
2. 鉛筆マーク（編集）を押し、バージョンを **「新バージョン」**、アクセスできるユーザーを **「全員」** にして「デプロイ」を押す。
3. （必要に応じて初回やスコープ追加時）アクセス権限の承認画面が出た場合は承認を完了する。

### 3. プロンプト改善・即時反映運用（完全ノーデプロイ）

#### プロンプト設計・改修の原則（ガバナンス）
本システムのプロンプト改修にあたっては、以下の原則を厳格に順守します（[AGENTS.md](AGENTS.md) 参照）：
1. **Principles over Examples（具体例排除・原則ベース）**:
   プロンプト内に行動の具体名や時刻の具体例をハードコードせず、負荷（極小〜高）・覚醒度・所要時間・姿勢場所などの「客観的属性」で定義。
2. **Generalizability（普遍性）**:
   特定シーンへの場当たりパッチを排し、普遍的な生活力学・状態遷移として捉える。
3. **データとプロンプトの完全分離（カプセル化）**:
   生活習慣や運動の具体肢は `lifestyle_habits` に、周期記録は `cycle_stamps` に集約し、プロンプト内へデータを癒着させない。

#### 即時反映フロー
プロンプトの調整や改善は、**GASの再デプロイを行わずに即座に本番反映**できます：

- **Antigravity（AI）からの直接書き換え**:
  ```bash
  # モジュール一覧の確認
  node scripts/sheet-cli.js get-prompt
  # 特定モジュールの確認
  node scripts/sheet-cli.js get-prompt prompt_phase_c
  # 特定モジュールの更新
  node scripts/sheet-cli.js set-prompt prompt_phase_c "新しいプロンプト内容"
  ```
- **手動での直接編集**:
  スプレッドシートの `memory` タブを開き、対象モジュールのセルを直接編集しても即時反映されます。
- **コードからの初期同期**:
  コード上の最新デフォルトプロンプト群をスプレッドシートへ一括同期したい場合は、GASエディタで `syncDefaultPromptsToSpreadsheet` を実行します。

### 4. 初期設定・検証テスト関数（`Setup.gs`）

- **初期構築・メンテナンス**:
  - `setupSpreadsheet`: スプレッドシートの全6タブとヘッダーを自動初期化
  - `setupTriggers`: 毎日午前3時の深夜バッチタイマートリガーを自動登録
  - `setupLineRichMenuFromSetup`: LINEトーク画面下部にリッチメニューを登録・有効化
  - `syncDefaultPromptsToSpreadsheet`: コード上の最新全モジュールプロンプトをスプレッドシートの `memory` シートに一括同期
- **検証テスト（完全ドライラン）**:
  - `testCustomScenario`: 過去の会話ログや指定時刻（ターン）をシミュレートし、2段階アーキテクチャの推論・トークン消費・アクション出力を安全にドライラン検証
  - `testGeminiConnection`: LiteモデルとFlashモデルの両方のAPI接続・疎通確認
  - `testDailyBriefingOutput`: デイリーブリーフィング生成ドライラン
  - `testMidnightBatchSimulation`: 深夜統合バッチの手動実行
