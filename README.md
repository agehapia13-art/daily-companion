# 生活伴走システム（LINE Bot × GAS × Gemini 3.8 Flash）

サウンドディレクター専属の生活伴走アシスタントとして、LINE・Google Apps Script (GAS)・Gemini 3.8 Flash・Googleスプレッドシート・Googleカレンダー・Notion API・Open-Meteoを完全統合したパーソナル自動化システムです。

---

## 🌟 システムの特徴と主要アーキテクチャ

1. **完全コストゼロ運用（LINE Reply API限定）**
   - Push APIは一切使用せず、全対話・通知を無料の **Reply API** のみで完結。
   - 深夜バッチも通知なしの完全サイレント処理。
2. **睡眠ファースト ＆ 起床連動（ファースト・ハロー方式）**
   - 起床時間（朝4時〜正午まで）の初回の発言（「作業する」「おはよ」等）の返信末尾に、**天気（最高/最低気温・降水確率）・当日活動時間帯（06:00〜24:00）の気圧急降下アラート・本日の予定・重要タスク（当日＆期限超過の未完了タスク）**をまとめたデイリーブリーフィングを自動合流（正午以降や2回目以降の発言では誤発動しないガード付き）。
   - **出社予定連動の天気取得**: 本日の予定（メイン＋家族共用「♪」予定）に「出社」が含まれる日のみ「自宅(磯子)＋職場(渋谷)」の両方の天気を取得・表示し、在宅日は「自宅(磯子)」のみを表示してノイズを排除。
   - **プログラム制御による二重配信防止**: AIの出力に任せず、`PropertiesService` とスプレッドシート `memory` の両面ガード（`isBriefingDeliveredToday` / `markBriefingDeliveredToday`）で1日1回だけ確実に配信。
3. **超低遅延レスポンス ＆ トークン極小化**
   - **思考トークン無効化（`thinkingBudget: 0`）**: Gemini Flashの内部思考プロセスによる課金・遅延を完全排除し、LINE Reply APIを最速実行。
   - **空キー省略ルール**: 通常の雑談時は `{"reply_text": "..."}` のみ出力させ、不要なJSONキー（`task_actions: []` 等）を出力させないことで出力トークンを最小化。
   - スプレッドシート更新等の重いI/Oは返信完了後に安全に非同期ライクに実行。
4. **安心の単一ユーザーセキュリティ（あなた専用）**
   - あなたのLINE User ID（`OWNER_USER_ID`）のみを受け付けるホワイトリスト認証。
   - 他者からのメッセージや偽造リクエストを即座に遮断し、予定・体調・タスクのプライバシーを保護。
5. **記憶の3層管理 ＆ 用語辞書（前提知識の厳格遵守）**
   - **短期記憶**: 当日の会話ログ（極小高密度フォーマット `HH:mm User: ... / AI: ...` で全ターン保持）。
   - **中期記憶**: `rolling_memory`（最近の関心・ログ：直近7〜10日分の活動・関心バッファ）。
   - **長期記憶**: `profile`（住居・家族・勤務形態などの恒久的事実。深夜バッチで厳格に代謝）。
   - **用語辞書**: 『ぽこあポケモン』『残響フラクタル』『ぱずぎり』などの独自用語・作品定義をAIが世間一般の作品と混同しないよう、コンテキストに常時注入。
6. **Web検索（Google Search Grounding）とタスク誤爆防止**
   - 「〇〇のイベントいつまで？」「〇〇のチケット発売日いつ？」等の質問時は、Web検索で最新・正確な期日や事実をリアルタイム調査。
   - **月間5,000回まで検索完全無料**: Gemini 3.8 Flash における Google Search グラウンディングは、**月間 5,000 リクエスト（1日あたり約160回）まで無料枠**が提供されています。個人運用の会話量であれば無料枠内で完全に収まるため、検索追加費用は**実質0円**で稼働します（超過時も1,000回あたり$14と低廉）。
   - 調べた時点では勝手にタスク追加せず、「タスクに追加しておきましょうか？」と確認を添え、次のターンで「追加して」と言われた際に初めて期限付きタスクとして登録。
7. **Googleカレンダー双方向連携 ＆ 家族共用カレンダー安全参照**
   - **メインカレンダー**: 読み取りおよび追加・削除に対応。毎週の曜日繰り返し予定（`recurrence_days: ["MON", "THU", "FRI"]`）にも対応し、重複単発予定を自動クリーンアップ。
   - **家族共用カレンダー（`FAMILY_CALENDAR_ID`）**: 【完全読み取り専用】。ユーザー担当の「♪」付き予定のみを抽出してデイリーブリーフィングやスケジュール把握に活用。
8. **自律性と対等性を尊重した行動提案 ＆ スマートなタスク管理**
   - **原則ベースの行動提案エンジン（4プール横断・4属性フィルタ・異種ポートフォリオ分散・同日重複排除）**:
     特定の定番行動（読書・音楽・メモ等）への偏りを防ぐため、[プール1: 未完了タスク / プール2: 未消化インプット / プール3: 専門スキルアップ・創作・ゲーム / プール4: 身体ケア・運動・生活手入れ] の全4ソースを横断検索。[所要時間 / 脳と身体の負荷 / 覚醒度 / 姿勢・場所] の4属性で現在のユーザー状態（時刻・体調・空き時間・直前の行動）と照合。複数案提示時は異なるプール・異なる負荷から組み合わせ、同日内の既出提案の再リピートを遮断。
   - **放置タスク・期限未設定タスクの隙間時間活用**:
     登録後7日以上経過したタスク（`[⚠️登録後7日以上経過]`）や期限未設定タスクのうち、手元で数分〜15分程度で終わる軽作業（ヘアブラシや道具の手入れ、小片付け等）は、食後やまったりした隙間時間に「サクッと片付けちゃいませんか？」と最優先で着手を後押し。
   - **行動宣言に対する時間軸の限定（1文完結・先回りの完全排除）**:
     「風呂洗ってお湯張ってくる」「ご飯炊いてくる」などの行動宣言時は、その宣言された行動への了解と送り出しの1文のみで即座に完結。「準備ができたら温まって〜」「沸いたら〜」「終わったら〇〇しよう」といった条件付きの先回りや後続フェーズへの言及を完全排除。
   - **大人の自律性尊重と予防的声かけ（小言）の排除**:
     ユーザーの年齢・属性に相応しい対等な大人としての距離感を保持。日常の生活行動や家事に対して、怪我・冷え・体調に関する予防的気遣いフレーズ（「〜に気をつけて」等）を口出ししない。
   - **主語・視点の厳密な分離（当事者挨拶・セルフケア感謝の禁止）**:
     AIは「聞き手・伴走者」であり行動の当事者ではない。ユーザーの食事や帰宅等の報告に対して当事者本人が使う言葉（「ごちそうさまでした」「ただいま」等）をAIが使うことや、ユーザー自身のセルフケアに対してAIがお礼（「ありがとうございます」）を言う主客逆転を厳禁化。
   - **「予定通り」連呼の禁止（監視員化の防止）**: スケジュールは大枠の目安であり、予定の消化をチェック・監視するような「予定通り〜」の表現を排除。
   - **当日のゲーム充足度連動 ＆ 30分クイック提案**: ゲーム・趣味の時間を最優先で確保。さらに当日の会話ログですでにゲームを満喫した形跡がある場合は、その後の「30分〜1時間程度のちょっとした空き時間」であっても、だらだら防止として［30分スケッチ / 楽器の運指・フレーズ練習 / 1パート打ち込み再現］などの短時間スキルアップや前倒しタスクを軽やかに提案。
   - **休日の先回りスケジュールブロック**: 木曜・金曜の夕方〜夜や平日の作業一段落時に週末カレンダーの空き枠を検知し、自発的にスキルアップ予定（午後の2時間ブロック等）を提案。
   - **「期限が当日ではないタスク」の前倒し提案**: 「締め切りが明日以降のタスク」や「期限未設定のタスク」に着目し、空き時間に応じた前倒し着手を促進。前倒し可能なタスク（締切・制作・購入等）と、特定日限定タスク（ゴミ出し・特定日イベント・発売日等その日でないとできないタスク）を厳密に判別し、フライング提案を防止。
   - **体調言及のインターバル原則（執拗なリピート禁止）**: 朝のログ等で不調があっても、ユーザーから再度言及されない限り、毎ターンのようにお腹の温めや冷えを壊れたレコードのようにリピート言及し続けることを厳禁化。
   - **返信フォーマットの可変長化（ノルマ撤廃）**: 義務的な「メイン2〜3文 ＋ 気遣い1行」の固定テンプレを撤廃し、文脈に応じた1〜3文の可変長へ刷新。日常報告や行動宣言には余計な小言を挟まず1〜2文で軽快に完結。
   - **自発的意志の即時タスク・予定登録（お伺いゼロ化）**: ユーザーが「〜しないと」「〜直さないと」「〜整理したいな」「明日〜行く」と口にした場合は、確認を挟まず即座にタスク（またはカレンダー予定）へ登録し事後報告。
   - **文脈プレフィックス付与 ＆ 締切時刻ルール**: タスク名は「対象/プロジェクト：具体的なタスク内容」形式で自己完結。時間指定は末尾に `（〜12:00まで）` 等と明記。
   - **DB操作通知の一本化**: `✅ タスク完了`、`📝 タスク追加/更新`、`🛒 買い物追加` 等はプログラム側（`Webhook.js`）が末尾に1行だけ確実に自動付加して重複を防止。
9. **スプレッドシート連動による完全ノーデプロイ・プロンプト運用（Antigravity連携）**
   - **完全ノーデプロイでのプロンプト即時反映**:
     `src/Gemini.js` は、スプレッドシートの `memory` タブにある `system_prompt` を最優先で読み込み（未設定時はコード内デフォルトへ自動フォールバック）。毎ターンの `getMemory()` 一括取得に相乗りしているため、**追加の読み取り通信遅延は「完全ゼロ（0ms）」**。プロンプトの調整・改善時にGASエディタでの再デプロイ（新バージョン発行）が一切不要となり、スプレッドシートの該当セルを書き換えるだけで次のLINEメッセージから即時反映。
   - **Antigravityからの直接読み書き（サービスアカウント連携）**:
     Google Cloud サービスアカウント（`service-account.json`、Git管理外）および専用CLI（`scripts/sheet-cli.js`）を通じて、Antigravity（AI）がチャットから直接スプレッドシートのプロンプト、メモリ、最新ログを自由自在に読み書き可能。
   - **1クリック初期同期**:
     `Setup.gs` の `syncSystemPromptToSpreadsheet` を実行するだけで、コード上の最新プロンプトをスプレッドシートの `memory` シート（`system_prompt` 行）へ自動同期可能。
10. **深夜03:00統合バッチ (Notion日報・月報連携)**
    - 当日の会話ログ、完了タスク、および当日に消化完了したインプット作品（映画・音楽・本・ゲーム等）を集約し、GeminiでMarkdown日報を生成してNotion日報DBへ投稿。
    - **Notionリッチテキスト完全対応**: 太字（`**...**`）のインラインアノテーション、区切り線（`divider` ブロック）にネイティブ対応。
    - **思い出の写真自動埋め込み**: LINEで送信された画像（Google Drive保存）の中から、料理・風景・記念スクショなど日記として価値のある特筆すべき写真を厳選し、Notion日報および月報に自動埋め込み。
    - **振り返りの質向上**: AI側の返答・推測・相槌をインプットから除外して体調等の勝手な創作を防止。全体の講評や物語的なオチ付け（「〜な1日でした」等）を禁止し、箇条書き主体で数秒で把握できる視認性を確保。一方で過度な短縮による意味不明化を防ぎ、経緯・理由・結果が自立して思い出せる具体性を維持。AIへの指摘を自分の気づきにすり替える美談化や、翌日使われない「明日への引き継ぎメモ」を廃止。
    - **Notion投稿成功を確認してから**ログをクリアするデータ保護設計。また、Gemini APIの一時的な高負荷（503/429）に対する自動リトライ機構を全呼び出しに完備。
    - ルーティンタスクの重複生成防止ガード（同名タスクが未完了の場合はスキップ）。
    - 毎月1日には前月日報を日付昇順で自動集約し、月間ハイライト・思い出ジャーナルをNotion月報DBへ投稿。
11. **生活伴走Webダッシュボード（GitHub Pages × LIFF × LINEリッチメニュー）**
    - **スプレッドシートの`logs`以外（全5タブ）をスマホで直感操作できる専用SPA**:
      - 🌿 **タスク**: 未完了タスクを全件一覧表示。プレフィックス（プロジェクト）ごとに自動グループ化し、各グループ内は**直近の締め切り順**で優先表示。「📂 グループ別」と「📅 締切順一覧」のワンタップ切り替えや、長期タスクの「🌱 登録から○日」バッジ表示、完了時の「元に戻す」トースト通知。さらに**タスクカードの本文をタップすると編集モーダルが開き**、カードUIを一切圧迫せずにタスク名・期限・メモの編集や破棄が可能。
      - 🛒 **買い物**: カテゴリ別未買リスト、ワンタップ購入済チェック、クイック追加、本日購入済アイテムのチェック解除。
      - 💡 **ストック**: 映画・音楽・本・ゲーム等の未消化作品一覧、消化チェック、新規追加、および本日消化済アイテムのチェック解除。
      - 🔄 **周期・記憶**: 美容院や弦交換などの「あれから○日経過」と「✨ 今日やった」ワンタップ更新（手動テキスト編集も可）、定期ルーティン一覧、およびAIの『用語辞書』『プロフィール』『最近の関心・ログ』『体調・睡眠サマリー』の閲覧と直接編集。
    - **GitHub Pages × LIFF 連携によるネイティブアプリ体験**:
      - **公開URL**: `https://agehapia13-art.github.io/daily-companion/`
      - **GitHubリポジトリ**: `https://github.com/agehapia13-art/daily-companion`
      - フロントエンド（`docs/index.html`）を **GitHub Pages** 上でホストし、裏側のデータ読み書きのみGASのJSON APIと通信する構成。
      - GAS特有の「このアプリケーションはGoogle Apps Scriptのユーザーによって…」という上部警告バーや二重iframe隔離制限を完全解消。
      - **LINEトーク画面への自動発言**: ダッシュボード上でタスク完了・買い物購入・インプット消化・周期メンテナンスを実施すると、LIFF（`liff.sendMessages`）を通じて**LINEトーク画面にあなた自身の緑の吹き出しで自動発言**され、AIの返信とともに当日ログ（`logs`シート）へ自然に記録。
      - **自動パラメータ引き渡し＆フォールバック**: リッチメニューから開くと `tab`, `key`, `liffId`, `api` が自動引き渡しされ `localStorage` に記憶。万が一のGASコールドスタートや通信不調時も、15秒タイムアウト判定とエラー境界により永久スピナー停止を防止。

## ⚙️ 環境変数（Script Properties: 全15項目）

Google Apps Script プロジェクトの「プロジェクトの設定」>「スクリプト プロパティ」に以下を設定してください。

| キー | 必須 | 説明 | 設定例 / 備考 |
| :--- | :---: | :--- | :--- |
| `OWNER_USER_ID` | ○ | **あなたのLINE User ID** | LINE公式アカウントと会話した際の `event.source.userId`（`U...` 33桁） |
| `LINE_CHANNEL_ACCESS_TOKEN` | ○ | LINE Messaging API チャネルアクセストークン（長期） | LINE Developers コンソール |
| `GEMINI_API_KEY` | ○ | Google AI Studio APIキー | Google AI Studio |
| `SPREADSHEET_ID` | ○ | 連携するGoogleスプレッドシートのID | スプレッドシートURLの `/d/{ID}/edit` 部分 |
| `DRIVE_FOLDER_ID` | ○ | 受信画像を保存するGoogle DriveフォルダID | DriveフォルダURLの `/folders/{ID}` 部分 |
| `NOTION_API_KEY` | ○ | Notion Internal Integration Secret | Notion Developers（`secret_...`） |
| `NOTION_DAILY_DB_ID` | ○ | Notion日報データベースID | Notion日報DBのURL内の32桁英数字 |
| `NOTION_MONTHLY_DB_ID` | ○ | Notion月報データベースID | Notion月報DBのURL内の32桁英数字 |
| `HOME_LATITUDE` | ○ | 自宅（横浜市磯子区）の緯度 | `35.3970` |

## 📊 スプレッドシート構造（全6タブ）

1. **`logs`**（当日会話ログ）: `[時刻, 発言者, メッセージ, 画像URL, AI返答]`（※機械用一時バッファ。深夜バッチでNotion投稿後にクリア）
2. **`tasks`**（単発タスク）: `[タスクID, タスク名, 期限, ステータス(未完了/完了/破棄), 登録日, 完了日, メモ]`
3. **`routines`**（繰り返し定義）: `[ルール名, タイプ(day_of_week/day_of_month/interval_days), 設定値, 最終生成日, メモ]`
4. **`shopping`**（買い物リスト）: `[品名, カテゴリ, ステータス(未買/購入済/破棄), 登録日]`
5. **`input_stock`**（映画・音楽・本のストック）: `[種別, タイトル, メモ, ステータス(未/完/破棄), 消化日]`
6. **`memory`**（中長期記憶・システム制御）: `[キー, 値]`
   - `profile`: ユーザー属性・生活前提条件
   - `dictionary`: 用語辞書（客観的前提知識）
   - `rolling_memory`: 最近の関心・ログ（直近7〜10日分の活動・関心バッファ）
   - `weekly_summary`: 直近数日間の疲労・睡眠サマリー
   - `cycle_stamps`: 周期メンテナンス ＆ 能動的音楽スキルアップ最終実施記録（美容院、弦交換、シーツ洗濯、ピアノ/ギター/トロンボーン演奏、楽曲制作、打ち込み再現、スケッチ等）
   - `weather_info`: 今日の天気・最高/最低気温・降水確率（出社予定がある日のみ職場・渋谷も併記）
   - `pressure_alert`: 当日活動時間帯（06:00〜24:00）の6時間以内5hPa気圧急降下アラート（TRUE/FALSE）
   - `briefing_delivered_date`: 本日ブリーフィング配信済み日付（YYYY-MM-DD）
   - `monthly_report_ready`: 月報作成完了フラグ（TRUE/FALSE）
   - `system_prompt`: スプレッドシート側から注入可能な完全システムプロンプト（設定時はコード内デフォルトより最優先適用され、GASの再デプロイ不要でプロンプトを即時反映可能。読み取り遅延0ms）
   - `custom_system_prompt`: スプレッドシート側から注入可能な追加カスタムプロンプト（レイアウト・改行指示等）

## 🛠️ 開発・デプロイ運用ルール

### 1. 開発とコード反映フロー（Antigravity / AI担当）

本プロジェクトは **全コードをGit（GitHub）で一元管理** し、GASへは `clasp push` で直接同期します。
コード修正時は、常に以下のワンストップフローで構文チェック・GAS反映・Git保存を行います：

```bash
# 1. src/ 配下の全ファイル構文チェック
npm run check

# 2. clasp でGASプロジェクトへコードを直接プッシュ (src/ 配下をファイル分割のまま同期)
npm run push   # (npx clasp push --force)

# 3. (ダッシュボード画面変更時のみ) docs/index.html を再ビルド
npm run build:dashboard

# 4. GitHubへ最新コードと変更履歴を保存（毎回必ずコミット＆プッシュ）
git add . && git commit -m "feat/fix: 変更内容の概要" && git push origin main
```

> [!IMPORTANT]
> **権限承認の都合上、AI側は `clasp push`（コード反映）および `git push`（リポジトリ保存）までを実施し、GASのデプロイコマンドは実行しません。**

### 2. GASエディタ側でのデプロイ更新（ユーザー手動担当）

Googleアカウントの権限設定・スコープ承認が必要となるため、**コードプッシュ後のWebアプリのデプロイ（新バージョン発行）はユーザー自身がGASエディタ上で行います**：

1. GASエディタ右上の **「デプロイ」＞「デプロイを管理」** を開く。
2. 鉛筆マーク（編集）を押し、バージョンを **「新バージョン」**、アクセスできるユーザーを **「全員」** にして「デプロイ」を押す。
3. （必要に応じて初回やスコープ追加時）アクセス権限の承認画面が出た場合は承認を完了する。

### 3. プロンプト改善・即時反映運用（完全ノーデプロイ）

プロンプトの調整や改善は、**GASの再デプロイ（新バージョン発行）を行わずに即座に本番反映**できます：

- **Antigravity（AI）からの直接書き換え**:
  チャットで「プロンプトの〇〇を直してスプレッドシートに反映して」と指示すれば、Antigravityが Google Cloud サービスアカウント（`service-account.json`）経由で `scripts/sheet-cli.js` を実行し、スプレッドシートの `memory` タブ（`system_prompt` セル）を直接更新します。
- **手動での直接編集**:
  スプレッドシートの `memory` タブを開き、`system_prompt` のセルをブラウザ上で直接編集しても同様に即時反映されます。
- **コードからの初期同期**:
  コード上の最新デフォルトプロンプトをスプレッドシートへ同期させたい場合は、GASエディタで `syncSystemPromptToSpreadsheet` を実行します。

※スプレッドシートの `system_prompt` 読み取りは、LINE受信時の `getMemory()` 一括取得に相乗りしているため、**追加の通信遅延（オーバーヘッド）は「完全ゼロ（0ms）」** です。
※`service-account.json` は `.gitignore` に登録されており、GitHubへ漏洩しないよう物理的に除外されています。

### 4. LINE Developers (LIFF) 設定

1. LINE Developers コンソールの **LINEログインチャネル** ＞ **「LIFF」タブ** を開く。
2. **エンドポイントURL**:
   `https://agehapia13-art.github.io/daily-companion/`
3. **Scopes**:
   `chat_message.write`, `profile`（または `openid`）にチェック。
4. **モジュールモード**:
   オフのままで正常動作します。

### 5. 初期設定・手動操作（`Setup.gs`）

手動で実行したい設定やテストは、すべて **`Setup.gs`** を開けば一番上に揃っています：

- `setupSpreadsheet`: スプレッドシートの全6タブとヘッダーを自動初期化
- `syncSystemPromptToSpreadsheet`: コード上の最新システムプロンプトをスプレッドシートの `memory` シート (`system_prompt` 行) に同期保存
- `setupTriggers`: 毎日午前3時の深夜バッチタイマートリガーを自動登録
- `setupLineRichMenuFromSetup`: LINEトーク画面下部に4分割リッチメニューを自動登録・有効化（GitHub PagesおよびLIFF URLを自動構成）
- `testWebhookSimulation`: LINE受信テスト
- `testWebSearchSimulation`: Web検索テスト
- `testMidnightBatchSimulation`: 深夜バッチ手動実行テスト
- `testMemoryLifecycleSimulation`: 記憶代謝テスト
- `testPromptComparisonSimulation`: 新旧プロンプト比較ドライラン（主要シーン一括実行）
- `testScene1_EveningSnackWaiting` 〜 `testScene6_SickAndBored`: 各生活シーン（食後お菓子待ち、ゲーム後余白、就寝前、朝ゆとり、風呂沸かし宣言、体調不良×暇）の単体新旧比較テスト

## 🚀 今後のロードマップと最適化プラン

### 1. 2モデル体制（動的ルーター × メイン思考AI）とプロンプトモジュール化

* **背景・目的**:
  * 現行システムは毎ターン約6,000〜7,000トークンを消費（システムプロンプト約7,200文字 ＋ 全シート情報）。
  * **2027年1月よりGemini 3.8 Flashの導入プロモーション価格（$0.75/$3.75）が終了し、通常価格（$1.50/$7.50の2倍）へ移行**するため、事前の抜本的なトークン削減対策を実施。
  * 日常会話の約8割（「お風呂行く」「眠い」「ご飯食べた」等の短文報告・雑談）ではカレンダーやタスク全件、Google検索ツールは一切不要であり、ノイズ排除による回答精度向上とコスト圧縮を同時に実現する。
* **アーキテクチャ構成**:
  1. **1段目: 超軽量ルーターAI（Intent Classifier）**:
     * 候補: `gemini-2.5-flash-lite`（高速・超低コスト・日本語口語に強い）。
     * ※将来的に `Jev`（TypeSafe AI）、`Microsoft-Decision-1`、`Groq` などの判断特化（System 1）モデルへ容易に差し替え可能な疎結合インターフェースで設計。
     * 入力発話から「意図モード（雑談報告 / 提案相談 / タスク操作 / スケジュール確認）」および「必要リソース（calendar / tasks / input_stock / search）」を数百トークンの超軽量JSONで瞬時に判定。
  2. **2段目: メインAI（Gemini 3.8 Flash）**:
     * ルーターの判定結果に基づき、**「共通基盤プロンプト ＋ 意図別モジュールプロンプト」のみを動的合成**し、**必要なシートデータのみを注入**。
     * 雑談時はプロンプト文字数を約1,500文字（約80%カット）、平均消費トークンを現状の約1/4以下（約1,760トークン）へ圧縮。
  * **コスト効果**: 2027年1月の値上げ後でも月額400〜500円程度に抑制可能（現状のプロモ価格350円/2週よりも安価に運用）。

### 2. 本番環境（Production）と開発環境（Development）の完全分離

2モデル体制やプロンプトの大規模改修を安全に行うため、現在生活動線に組み込まれている本番LINEボットを停止させずに開発・検証できるデュアル環境を構築予定：

* **本番環境（Production）**:
  * 本番LINE Botチャネル ＋ 本番GASプロジェクト ＋ 本番Googleスプレッドシート ＋ 本番Notion DB。
  * 日常の安定稼働を最優先とし、検証済みの安定版コード・プロンプトのみを反映。
* **開発環境（Development）**:
  * 開発用LINE Botチャネル（またはローカルCLI / GASシミュレーション） ＋ 開発用GASプロジェクト ＋ 開発用スプレッドシート（本番の複製）。
  * Gitブランチ（`develop`）およびclasp環境を分離し、ルーターの実験やプロンプトのABテストをノーリスクで実施可能にする。
